## Karar bekleyen 1 — Cinema Scale frontend fallback'i

**Yer:** `frontend/src/containers/results/ResultsPage.tsx:41-124` (`calcCinephileScore`)

Backend `compute_cinema_scale` (`backend/app/analysis_utils.py`, `cine_v2`) ile frontend'deki
bu 80 satırlık kopya **aynı formülü** uyguluyor: aynı ağırlıklar (coğrafya 25 / dönemsel 20 /
dil 15 / hacim 15 / tür 15 / yönetmen 10), aynı Shannon entropisi, aynı baskınlık cezaları,
aynı etiket eşikleri.

Frontend kopyası `ResultsPage.tsx:190`'da **yalnızca fallback**:
`stats?.sinefil_meter?.score ?? calcCinephileScore(stats)`. Yani kullanıcı normalde her zaman
backend skorunu görüyor. Bu "iki farklı skor gösteriliyor" hatası değil — çift bakım yükü.

İki gerçek sapma var:
1. `ResultsPage.tsx:102` yılı **`2026` olarak hardcode ediyor**, backend `datetime.now().year`
   kullanıyor. Her yıl başında sessizce sapar.
2. Backend gerçek `median_release_year` kullanıyor; frontend on-yıl orta noktalarının ağırlıklı
   **ortalamasıyla** tahmin ediyor. Medyan ≠ ortalama.

**Seçenekler:**
- **(a)** Fallback'i tamamen sil, skor yoksa Cinema Scale bölümünü gizle. `CLAUDE.md` backend'i
  kanonik sayıyor; 80 satır ve sapma riski gider.
- **(b)** Fallback kalsın, sadece hardcoded `2026` düzeltilsin. Eski payload'larda ekran boş kalmaz.

Not: `CLAUDE.md`'deki kural — TMDB popülerliği bu skora **asla** geri sokulmayacak.

## Karar bekleyen 3 — `ScrapeAnalysisEmpty` docstring/kod çelişkisi

**Yer:** `backend/app/services/scrape_pipeline.py:38-49`

Docstring `scraper_ok=True`'yu şöyle tanımlıyor: *"scraper bir film sayısı gördü ama parse boş
döndü — muhtemelen scraper bug'ı"*. Kod ise tersini yapıyor:

```python
scraper_ok = sources.film_count > 0 and (len(sources.diary) > 0 or len(sources.grid) > 0)
```

Sonuç: 412 film ilan eden ama tek satır parse edilemeyen bir profil `scraper_ok=False` alıyor,
dolayısıyla 500 (scraper bug'ı) yerine "profil boş" muamelesi görüyor.

**Önceden var olan bir tutarsızlık** — bugünkü `87edfe7` düzeltmesinin kapsamı değildi, o yüzden
bilinçli olarak dokunulmadı. Karar: docstring mi koda uyacak, kod mu docstring'e?

İkincisi seçilirse `backend/tests/test_analysis_period.py` içindeki
`test_parse_failure_behind_a_real_film_count_is_not_blamed_on_the_period` testi bilerek
`scraper_ok` iddiasını içermiyor — oraya eklenebilir.

## Çalışırken bilinmesi gereken tuzaklar

- **Yerel `pip install -r requirements.txt` bu makinede çalışmaz.** Ortam Python 3.14 ve
  `numpy` için hazır wheel yok; kaynaktan derlemeye çalışıp derleyici hatası veriyor
  (`evex512 is unknown`). Bağımlılık doğrulaması **Docker ile** yapılmalı:
  `cd backend && docker build -t x . && docker run --rm -e TMDB_API_KEY=dummy x sh -c "pip install -q pytest pytest-asyncio httpx; python -m pytest -q"`

  regresyonunu yakalamaz. `/smt` rotası dev fixture'ıyla results ekranını anında yüklüyor
  (üretimde `prebuild` fixture'ı siliyor — bu kasıtlı).
- **Grafikler lazy-mount.** Results sayfasının tepesinde `.recharts-wrapper` sayısı 0'dır;
  görmek için aşağı kaydırmak gerekir.
